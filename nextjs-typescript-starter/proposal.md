# H5 英语单词学习项目需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | H5 英语单词学习项目 |
| 文档版本 | v1.0 |
| 产品形态 | 移动端 H5，兼容桌面浏览器预览 |
| 技术项目 | `nextjs-typescript-starter` |
| 登录参考 | `app/login/page.tsx`、`app/register/page.tsx`、`app/auth.ts` |
| 单词数据参考 | `../danci-admin/temp/PEPXiaoXue3_1.json` |
| 核心目标 | 浏览单词书、登录注册、连续学习单词、记录并恢复学习进度、查看单词详情 |

## 2. 项目背景

当前项目已有基于 NextAuth Credentials、邮箱和密码的登录注册基础代码。本次需要在此基础上实现一个适合手机使用的英语单词学习 H5。

用户可以在未登录状态下浏览全部单词书；选择单词书学习时需要登录。登录后，系统持续保存用户在每本单词书中的学习进度，下次进入时自动从上次已学单词的下一词开始。

## 3. 产品目标

1. 为用户提供简洁、低干扰的单词学习体验。
2. 支持邮箱和密码登录、注册，并复用项目已有认证逻辑。
3. 支持按单词书学习，并在多次访问之间保存进度。
4. 首页根据登录状态展示不同内容。
5. 单词学习卡片保持简洁，复杂内容放在详情页展示。
6. 页面优先适配宽度 320px～480px 的移动设备。

## 4. 本期范围

### 4.1 包含范围

- 首页。
- 我的页面。
- 底部双 Tab 导航。
- 登录、注册 Popup。
- 单词书列表。
- 最近学习。
- 单词卡片学习页。
- 单词详情页。
- 用户学习进度保存与恢复。
- 退出登录。
- 基础加载、空数据和错误状态。

### 4.2 暂不包含

- 单词书和单词的后台编辑功能。
- 收藏、错词本、测试、拼写练习。
- 排行榜、积分、连续打卡。
- 第三方账号登录。
- 离线学习。
- 语音识别和跟读评分。
- 付费和会员功能。

## 5. 用户角色

### 5.1 游客

- 可以进入首页。
- 可以浏览全部单词书。
- 不展示最近学习。
- 不产生学习进度。
- 点击任意单词书后，进入“我的”页面并自动弹出登录 Popup。

### 5.2 已登录用户

- 可以浏览全部单词书。
- 有学习记录时可以看到最近学习。
- 可以进入单词学习页和单词详情页。
- 可以保存并恢复每本单词书的学习进度。
- 可以在“我的”页面查看邮箱、学习进度并退出登录。

## 6. 信息架构与路由建议

| 页面 | 建议路由 | 登录要求 | 底部 Tab |
| --- | --- | --- | --- |
| 首页 | `/` | 否 | 显示 |
| 我的 | `/me` | 否 | 显示 |
| 单词学习 | `/learn/[bookId]` | 是 | 隐藏 |
| 单词详情 | `/words/[wordId]` | 是 | 隐藏 |
| 原登录页 | `/login` | 否 | 不作为 H5 主入口，保留为兼容入口 |
| 原注册页 | `/register` | 否 | 不作为 H5 主入口，保留为兼容入口 |

说明：

- 首页和“我的”是一级页面，固定显示底部 Tab。
- 学习页和详情页是沉浸式二级页面，使用顶部返回按钮，不显示底部 Tab。
- 未登录用户点击单词书时，跳转地址建议为：
  `/me?auth=login&redirect=/learn/{bookId}`。
- 登录成功后读取 `redirect` 参数，返回用户原本选择的单词书。

## 7. 全局布局与视觉要求

### 7.1 H5 容器

- 页面最小宽度支持 320px。
- 内容最大宽度建议为 480px。
- 桌面浏览器中页面居中，两侧使用浅色背景。
- 页面主体需要为底部 Tab 预留空间，避免内容被遮挡。
- 底部导航需要适配 `safe-area-inset-bottom`。

### 7.2 视觉原则

- 整体简洁、轻量，突出单词与学习操作。
- 主色不超过一种，其他颜色用于状态提示。
- 按钮和可点击区域高度不小于 44px。
- 单词卡片避免堆叠过多信息。
- 封面比例统一，加载失败时显示默认占位图。

### 7.3 底部 Tab

- 固定在页面底部。
- 包含“首页”和“我的”两个入口。
- 当前页面需要有明确的激活态。
- 点击当前 Tab 时保持当前位置，不重复创建历史记录。

## 8. 核心业务规则

### 8.1 最近学习

- 只对已登录用户展示。
- 取该用户 `updatedAt` 最新的一条单词书学习进度。
- 用户没有任何学习进度时，整个“最近学习”模块不渲染，不显示空占位。
- 点击最近学习卡片后继续该单词书。
- 继续学习时，应找到 `wordRank` 大于上次完成词序的第一条单词。

### 8.2 单词书学习起点

- 用户第一次学习某本单词书：从 `wordRank` 最小的单词开始。
- 用户已有进度：从上次已完成单词的下一条开始。
- 不直接重复显示上次已经点击“下一个”的单词。
- 如果单词序号不连续，不能使用简单的 `lastWordRank + 1` 查询；应查询：
  `wordRank > lastWordRank`，再按 `wordRank ASC` 取第一条。
- 如果已经完成最后一个单词，进入完成状态，可选择“重新学习”或“返回首页”。

### 8.3 进度保存时机

- 当前单词展示时不立即算作已学。
- 用户点击“下一个”时：
  1. 将当前单词标记为已完成。
  2. 更新该用户在当前单词书中的 `lastWordRank`、`lastWordId`、`learnedCount` 和 `updatedAt`。
  3. 加载下一条单词。
- 同一个用户和同一本单词书只能存在一条进度记录，使用唯一约束保证。
- 用户打开详情页再返回时，仍停留在原学习卡片；查看详情本身不推进进度。

### 8.4 登录拦截

- 游客点击单词书时不直接进入学习页。
- 系统保存目标单词书和目标路由，跳转至“我的”。
- “我的”页面自动打开登录 Popup。
- 用户关闭 Popup 后停留在“我的”页面。
- 登录成功后跳转到最初选择的学习页。
- 注册成功后切换至登录状态并预填邮箱；用户完成登录后再进入目标学习页。

## 9.5 登录/注册 Popup

### 展现形式

- 移动端使用底部弹出的 Popup/Bottom Sheet。
- 有半透明遮罩。
- 点击遮罩或关闭按钮可以关闭。
- 键盘弹起后，输入框和提交按钮不能被遮挡。

### 登录模式

- 邮箱。
- 密码。
- 登录按钮。
- 切换到注册。

- 注册按钮。

### 登录注册规则

- 复用 `app/auth.ts` 中的 NextAuth Credentials 登录方式。
- 注册复用 `app/register/page.tsx` 的用户查询、密码哈希和用户创建逻辑。
- 邮箱提交前需要去除首尾空格并转成小写。
- 邮箱必须符合邮箱格式。
- 密码建议限制为 8～128 位。
- 邮箱必须唯一。
- 密码只能保存哈希值，不能保存或记录明文。
- 登录和注册接口返回通用错误文案，不能暴露用户是否存在等敏感细节。
- 登录按钮提交期间需要禁用，防止重复提交。

## 9.8 单词详情页

### 页面内容

详情页读取 `words.content` 的完整 JSON，根据字段是否存在按顺序展示以下模块：

1. 单词标题。
2. 英式、美国音标。
3. 释义列表。
4. 例句列表。
5. 短语列表。
6. 同近词。
7. 同根词。
8. 记忆方法。

### 模块字段映射

| 模块 | JSON 字段 | 渲染规则 |
| --- | --- | --- |
| 单词 | `content.word.wordHead` | 优先使用，缺失时回退到 `words.headWord` |
| 单词业务 ID | `content.word.wordId` | 用于数据识别，不作为主标题展示 |
| 美式音标 | `content.word.content.usphone` | 存在时展示“美” |
| 英式音标 | `content.word.content.ukphone` | 存在时展示“英” |
| 通用音标 | `content.word.content.phone` | 英美音标均不存在时使用 |
| 中文释义 | `trans[].tranCn` | 每一项单独展示 |
| 英文释义 | `trans[].tranOther` | 存在时显示在中文释义下方 |
| 例句英文 | `sentence.sentences[].sContent` | 使用纯文本字段 |
| 例句中文 | `sentence.sentences[].sCn` | 存在时展示 |
| 短语 | `phrase.phrases[].pContent` | 与中文 `pCn` 成对展示 |
| 同近词 | `syno.synos[]` | 展示 `pos`、`tran` 和 `hwds[].w` |
| 同根词 | `relWord.rels[]` | 按 `pos` 分组，展示 `words[].hwd`、`words[].tran` |
| 记忆方法 | `remMethod.val` | 字段存在时展示 |
| 音频标识 | `ukspeech`、`usspeech`、`speech` | 不是可直接播放 URL，本期不直接播放 |

### 安全要求

- `sContent_eng` 中可能含有 `<b>` 标签，本期优先使用纯文本 `sContent`。
- 不允许直接对 JSON 内容使用未经净化的 `dangerouslySetInnerHTML`。
- 所有可选模块在数据不存在时不渲染。

## 11. 数据模型建议

## 11.1 已有 User 表

继续复用当前项目的用户表和 Credentials 登录逻辑，但正式实现时应通过 Drizzle Schema 和迁移管理表结构，不应在每次请求中动态创建数据表。

建议约束：

- `id`：主键。
- `email`：非空、唯一、统一转为小写。
- `password`：非空，只保存密码哈希。

## 11.2 已有 books 表

| 字段 | 用途 |
| --- | --- |
| `id` | 数据库主键 |
| `title` | 单词书标题 |
| `wordCount` | 单词总数 |
| `coverUrl` | 封面地址 |
| `bookId` | 单词书业务 ID，唯一 |
| `tags` | 标签数组 |

## 11.3 已有 words 表

| 字段 | 用途 |
| --- | --- |
| `id` | 数据库主键 |
| `wordRank` | 单词在词书中的排序 |
| `headWord` | 单词标题 |
| `content` | 完整详情 JSON |
| `bookId` | 关联 `books.bookId` |

## 11.4 新增 learning_progress 表

建议表名：`learning_progress`。

| 字段 | 类型建议 | 约束/说明 |
| --- | --- | --- |
| `id` | bigint identity | 主键 |
| `userId` | integer/bigint | 非空，关联用户 ID，删除用户时级联删除 |
| `bookId` | text | 非空，关联 `books.bookId`，删除词书时级联删除 |
| `lastWordId` | bigint | 最近完成的 `words.id`，可空 |
| `lastWordRank` | integer | 最近完成的顺序，初始为 0 |
| `learnedCount` | integer | 已完成数量，初始为 0，不得小于 0 |
| `createdAt` | timestamptz | 默认当前时间 |
| `updatedAt` | timestamptz | 每次推进进度时更新 |

约束：

- `UNIQUE(userId, bookId)`：一个用户在一本词书中只有一条进度。
- 进度更新需要使用 Upsert 或数据库事务，避免重复点击造成多条记录。
- `learnedCount` 不得超过当前词书实际单词总数。

## 12. 服务端接口/Server Action 建议

具体可以使用 Route Handler 或 Server Action，但所有身份和数据权限判断必须在服务端执行。

| 能力 | 方法与路径建议 | 登录要求 | 返回内容 |
| --- | --- | --- | --- |
| 获取全部词书 | `GET /api/books` | 否 | 词书元数据列表 |
| 获取最近学习 | `GET /api/me/recent` | 是 | 最近更新的进度和词书 |
| 获取全部学习进度 | `GET /api/me/progress` | 是 | 当前用户进度列表 |
| 获取学习起始词 | `GET /api/books/[bookId]/next` | 是 | 下一条单词和总进度 |
| 更新学习进度 | `PATCH /api/books/[bookId]/progress` | 是 | 更新后的进度和下一词信息 |
| 获取单词详情 | `GET /api/words/[id]` | 是 | 单词完整 content |
| 用户注册 | `POST /api/auth/register` 或 Server Action | 否 | 成功/错误状态 |
| 用户登录 | NextAuth `signIn('credentials')` | 否 | Session 和跳转结果 |
| 退出登录 | NextAuth `signOut()` | 是 | 清除 Session |

### 接口通用要求

- 未登录访问受保护接口返回 `401`。
- 用户只能读写自己的学习进度。
- 参数错误返回 `400`。
- 资源不存在返回 `404`。
- 接口错误返回用户可理解的中文文案。
- 服务端日志不能记录密码、Session Token 或完整认证信息。

      ↓

      ↓

## 14. 页面状态要求

每个数据页面都需要覆盖以下状态：

### 14.1 加载状态

- 首页单词书使用骨架屏。
- 最近学习与全部词书可以分别加载。
- 学习页加载时使用卡片骨架，不能闪现上一单词。
- 提交按钮显示“登录中”“注册中”“保存中”等状态。

### 14.2 空状态

- 没有最近学习：不展示模块。
- 没有单词书：显示“暂无可学习的单词书”。
- 我的页面没有进度：显示引导去首页选书。
- 某本词书没有单词：显示“该单词书暂时没有内容”，提供返回按钮。

### 14.3 错误状态

- 网络错误需要提供重试按钮。
- 进度保存失败不能跳到下一词。
- 封面加载失败显示默认封面。
- content JSON 结构异常时至少展示 `headWord`，详情页显示“详情暂不可用”。
- Session 过期时跳转“我的”并打开登录 Popup，同时保留目标学习路由。

## 15. 安全与隐私要求

- 密码必须使用现有 `bcrypt-ts` 逻辑进行哈希。
- 不在客户端、日志或错误响应中暴露密码哈希。
- 登录态必须由服务端 Session 判断，不能只依赖客户端状态。
- 所有进度接口必须校验当前 Session 中的用户 ID。
- 注册接口需要防止重复邮箱。
- 登录和注册提交建议增加限流，降低暴力尝试风险。
- 所有数据库写入使用参数化查询或 Drizzle ORM。
- JSON 中的 HTML 字段不能未经净化直接渲染。
- `redirect` 参数只允许站内相对路径，防止开放重定向。

## 16. 性能与兼容性要求

- 首屏只查询词书元数据，不在首页返回每个单词的完整 `content`。
- 学习页一次只读取当前词和必要的下一词信息。
- 详情页按单词 ID 单独读取完整 JSON。
- 单词书封面使用懒加载。
- 支持主流 iOS Safari、Android Chrome 和微信内置浏览器。
- 页面不可出现横向滚动条。
- 低速网络下仍能看到明确的加载反馈。

## 17. 可访问性要求

- 所有输入框必须有对应 Label。
- Popup 打开时焦点进入弹窗，关闭后焦点返回触发按钮。
- 图标按钮需要提供 `aria-label`。
- 颜色不能作为唯一状态提示。
- 正文和背景对比度需要满足基本可读性。
- “下一个”、登录、退出等主要操作支持键盘触发。

## 20. 关键实现注意事项

1. 现有 `app/db.ts` 会在请求中动态检查并创建 `User` 表，正式项目建议改成固定 Drizzle Schema 和迁移，避免并发与部署风险。
2. 当前 `auth.config.ts` 将已登录用户从非受保护页面重定向到 `/protected`，需要调整，否则登录用户无法停留在首页或“我的”。
3. 原 `/login` 和 `/register` 页面可以保留，但 H5 主流程应复用其服务端逻辑，不应在 Popup 中复制两套认证实现。
4. `words.content` 是结构不完全统一的 JSON，所有嵌套字段都必须按可选字段读取。
5. 不能使用数组下标推断下一词，必须根据 `wordRank` 排序查询。
6. 单词总数优先以数据库中实际关联单词数量为准；`books.wordCount` 可作为展示缓存，但需要注意两者可能不一致。
7. 进度保存接口必须支持幂等处理，防止用户快速点击造成重复累计。
8. 从详情页返回时应保持当前学习位置，不能误推进或回退进度。
